Field notes, case 01

MuddyWater

An Iran-linked espionage group, active since 2017 and reportedly tied to Iran's Ministry of Intelligence and Security.

This dragon doesn't burn the walls down. It gets invited through the front gate, then hides inside tools the castle already trusts.

Scroll to follow two real campaigns, page by page.

Page 1, the letter

A letter from a friend

In August 2025 the group used a real, compromised mailbox to send the phishing emails, so they looked like ordinary correspondence. They reached it through a NordVPN exit node in France.

Group-IB counted more than 100 government entities among the targets, across the Middle East, North Africa and international organizations.

What you'd see

  • Headerx-originating-ip points to a commercial VPN exit, not the sender's usual network.
  • Sign-inThe mailbox owner's sign-in logs show a login from that VPN range around the send time.

Page 2, the gate

"Enable content"

The attachment is a Word document showing blurred text. The victim is told to enable content to read it, and that click runs the VBA macro.

The macro writes a file to C:\Users\Public\Documents\ManagerProc.log and runs it. That file is the FakeUpdate loader.

What you'd see

  • Sysmon 1WINWORD.EXE as the parent of a new process. Security 4688 shows the same if command-line auditing is on.
  • Sysmon 11A file created under C:\Users\Public\Documents\ by Word.

Page 3, inside the walls

Moving into a tower

FakeUpdate decrypts its payload with AES and injects it into its own process: version 4 of the Phoenix backdoor.

Phoenix copies itself to C:\ProgramData\sysprocupdate.exe and changes the Shell value under Winlogon in the user's registry hive, so it starts again at every logon.

What you'd see

  • Sysmon 13Value set on HKCU\Software\Microsoft\Windows NT\CurrentVersion\Winlogon\Shell.
  • Sysmon 11sysprocupdate.exe written to C:\ProgramData\.
  • 4657Registry value change, only if a SACL is set on that key.

Page 4, calling home

Five days on the hill

Phoenix beacons over WinHTTP to screenai[.]online, behind Cloudflare. Its certificate gave away the real server, 159[.]198[.]36[.]115.

The server went up on 19 August 2025 and came down on the 24th. About five days of live command and control.

What you'd see

  • Sysmon 22DNS query for screenai[.]online.
  • Sysmon 3Outbound connection from sysprocupdate.exe, repeating on a steady interval.

Page 5, spare keys

Keys the castle already trusts

An open directory on the same server held legitimate remote-management tools, PDQ and Action1, and a custom browser stealer disguised as a calculator.

The stealer kills Chrome, Edge, Brave or Opera to unlock their files, decrypts saved logins and stages them in C:\Users\Public\Downloads\cobe-notes.txt.

Careful: these were found on the server. Group-IB says they were potentially used, not confirmed on a victim.

What you'd see

  • 7045A new service as an RMM agent installs. Security 4697 if service-install auditing is on.
  • Sysmon 5Browser processes ending together, then Sysmon 11 for cobe-notes.txt.

Page 7, a second campaign

Is this castle real?

Operation Olalampo started on 26 January 2026, again across MENA. One lure was an Excel sheet of accounting tables themed on a Middle East energy and marine services company.

The macro hides its payload as decimal text in a hidden form field, waits in nested loops to outlast sandbox sleep hooks, then drops C:\Users\Public\Documents\MicrosoftExcelUser.exe: the GhostFetch downloader.

GhostFetch quits if the castle looks fake: under 2 GB of RAM, under 2 CPU cores, fewer than 2 USB devices ever connected, no mouse movement, or a debugger slowing its clock.

What you'd see

  • Sysmon 1EXCEL.EXE starting MicrosoftExcelUser.exe from C:\Users\Public\Documents\.
  • Sysmon 11A copy written as burn.exe under %LOCALAPPDATA%\Microsoft\Windows\BurnUtill\.

Page 8, GhostBackDoor

A fake nameplate

GhostFetch pulls down GhostBackDoor and loads it in memory. The backdoor then picks its hiding place by privilege. With admin rights it installs a service named MicrosoftVersionUpdater, which is not a real Microsoft service.

If security tools are present it masks itself with the Recycle Bin CLSID. As a standard user it falls back to the Startup folder.

The service name will change. What a detection can hold onto is the shape of the install: a new own-process service, auto-start, running as LocalSystem, from a path outside C:\Windows and C:\Program Files.

What you'd see

  • 7045Service installed, with name, image path, start type and account in one event.
  • Sysmon 13Writes under HKLM\System\CurrentControlSet\Services\, made by services.exe, not by the implant.

Page 9, the operator's diary

The bot kept a diary

Another Olalampo payload, the Rust backdoor CHAR, takes orders through a Telegram bot. Group-IB watched that bot and read the operator's commands: whoami, ipconfig /all, domain admin lookups, and a daily 09:00 scheduled task named DailyUpdate to rerun the payload.

The log also held a slip. "tmux" typed on a Persian keyboard layout came out as فئعط. CHAR's debug strings carry emojis, which Group-IB reads as likely AI-assisted code.

What you'd see

  • 4698Scheduled task created, if object-access auditing is on. Sysmon 1 shows the schtasks.exe command line.
  • Sysmon 22DNS queries for api.telegram.org from a process that has no reason to talk to Telegram.
