T3 · X86-64 ASSEMBLY AND CALLING CONVENTIONS

Connect C to registers, the stack and calls

In practice: trace a short compiled function, identify its arguments and return value, and explain its stack frame.

Why a detection engineer needs it

Reading which register carries which API argument, judging a call stack in telemetry, and recognising a system-call stub all happen at instruction level.

The core instruction set

About 20 to 30 instructions read most programs (OST2 Arch1001): mov, lea, push, pop, call, ret, add, sub, xor, cmp, test, jcc, jmp, movzx.

Two syntaxes

Intel: mov dst, src (MSVC, IDA, NASM). AT&T: mov %src, %dst (GDB and objdump default). In GDB: set disassembly-flavor intel.

Idioms to recognise

xor eax, eax zeroes; lea does address maths without touching memory; writing a 32-bit register zero-extends to 64 bits.

Learn Windows x64 argument passing as well as the Linux examples most intro material uses (roadmap)

T4 · OPERATING SYSTEMS AND HARDWARE BOUNDARIES · OPTIONAL DEPTH

Every sensor sits on one side of the user/kernel line

In practice: explain virtual versus physical memory, and why a user-mode program needs system calls.

Limited direct execution

User code runs straight on the CPU, but I/O and privileged instructions need kernel mode. The OS regains control via traps and timer interrupts (OSTEP ch. 6).

Rings and CPL

Ring 0 kernel, ring 3 user. Privileged instructions such as mov cr3 or wrmsr fault with #GP in ring 3.

Virtual memory

Each process gets a private address space; the MMU maps pages to frames using tables rooted at CR3. Windows stores it per process as the DirectoryTableBase.

Interrupts and exceptions

#BP (3) from int3 = software breakpoints; #DB (1) = hardware breakpoints, single-step; #PF (14) = page fault; #GP (13).

T6 · MECHANISM · HOW A DLL GETS INTO A PROCESS

Load-time versus run-time linking

Load-time

  1. Linker records DLL names in the import table
  2. At start, each DLL is searched for and mapped
  3. Reference count up; DllMain(PROCESS_ATTACH)
  4. IAT slots get the real function addresses

Missing DLL: the process is terminated.

Seen as: import table entries; Sysmon 7 at start-up.

Run-time

  1. LoadLibrary(Ex) by name or path
  2. Mapped, or refcount up if already loaded
  3. GetProcAddress resolves an export
  4. FreeLibrary: refcount down, unmap at zero

Missing DLL: returns NULL; the process lives on.

Seen as: maybe no import entry; Sysmon 7 when it maps.

Delay-load imports sit in their own directory and resolve on first call, so their Sysmon 7 arrives later than process start.

Source: Microsoft Learn "Load-time dynamic linking", "Run-time dynamic linking", PE format (delay-load)

T13 · COM AND WMI FUNDAMENTALS

COM

WMI
